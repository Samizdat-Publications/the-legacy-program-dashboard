## Why it is not on master

It was merged and pushed, CI's `gate` job passed, and CI's **`app` job failed on C11**. The
deploy step was SKIPPED, so production was never affected and readers were served the
previous build throughout. Master was then reverted to `47a74ba` so it would not sit red.

**The cause is growth, and it was foreseen in CLAUDE.md.** That file records that C5 had
about 7px of clearance at 1920, that CI's fallback font wraps two more rows than Windows
does, and that nothing may take height from `.map-root` or `.hood`. The run took L0 from
137 to 149 nodes and the top-level map now needs more vertical height than exists:

| | rows needed | available | map mode | result |
|---|---|---|---|---|
| local | 51 rows, 954px | 938px | label | **C5 fails** (mode should be cell) |
| CI | 54 rows, 1008px | 938px | cell | C5 passes, **C11 fails** |

C11 asserts that every one of the 14 start-here highlights draws its own numbered chip on
the map. In cell mode individual chips collapse into counted cells, so only 9 do. **All 14
highlights are still in L0.** The map simply cannot draw them individually at this size.

## The decision this needs, and it is not a small one

1. **Cap or trim L0** so the map fits label mode at 1920 again. Editorial: L0 selection
   decides what the top-level map IS.
2. **Accept cell mode at 1920** and teach C11 that a numbered highlight may sit inside a
   counted cell rather than drawn as its own chip.
3. **Give the map more height**, which CLAUDE.md currently forbids.

Read this together with `notes/PACKED-LAYOUT-INK-2026-09-19.md` on the branch. They are the
second and third measurements this week showing the top-level map at a size limit, and they
should be answered together rather than one at a time.

## One process note, because it cost a red master

**`tools/state_snapshot.py --gate` does NOT run the app's checks.** The `app` job in CI
runs C1 to C21 separately. A session that changes board data must also run, from `app/`:

```
npm run build
npx vite preview --host 127.0.0.1 --port 4173 --strictPort   # background
npm run check
npm run check:poison
```

This run did the gate and not those, which is why a failure that reproduces locally in one
second was found by CI instead.
