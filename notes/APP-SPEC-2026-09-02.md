# The new shell: build specification (2 September 2026)

The product Design specified in `notes/DESIGN-RESPONSE-SHELL-2026-09-02.md` (read it in
full; its screens are under `notes/shots/design-2026-09-02/`), built as a hosted site, not
a single file. Stewart's decisions: public; working title **The Legacy Program Research
Terminal**; a site with dependencies and runtime data files is fine. Everything in
`CLAUDE.md` sections 2, 5 and 6 still governs: nothing invented, every check shown
rejecting bad input, size never encodes importance, labels one size chosen by space.

## 1. Stack and layout

| | |
|---|---|
| directory | `app/` at the repo root; the old shell (`tools/build_dashboard.py`, `dist/`) keeps building until the new one replaces it on the live site |
| toolchain | Vite 5, TypeScript, no UI framework. Plain DOM and canvas. `npm` at `app/package.json` |
| routing | hash router, exactly the scheme in the Design response section 2.1 |
| styles | one `app/src/styles/tokens.css` carrying the palette and type from the Design response section 1.1; components use the tokens only. IBM Plex Mono self-hosted under `app/public/fonts/` (no Google Fonts fetch) |
| data | static JSON under `app/public/data/`, generated by `tools/build_app_data.py` from the same sources the old pipeline uses, committed, fetched at runtime by path. The runtime-fetch rule becomes: same-origin `/data/*`, `/patents/*`, `/fonts/*`, and the analyst worker; nothing else |
| deploy | `app/dist/` to the Cloudflare Pages project `the-program` when the new shell replaces the old; until then a second Pages project `the-program-next` for review |
| analyst | the existing Worker at `https://the-program-analyst.stewartgregerson.workers.dev`; the client in `tools/analyst_patches.py` is ported to `app/src/analyst.ts` with the same request shape (`system` blocks, cache_control, `max_tokens`) |

## 2. Data contracts (`app/public/data/`)

All generated by `tools/build_app_data.py`. Every file carries `generated` (ISO) and
`source` (the git short hash of the research inputs). Ids are the board's ids.

### `index.json` (about 300 KB)
```
{ generated, source,
  counts: { nodes, people, entities, edges, claims:{1,2,3}, timeline, l0, threads, patents, sheets, foia:{requests, questions, nodes} },
  eras:   [ {id, label, sub, start, end} ],            // the five eras incl. "no-date"
  bands:  [ {id, label} ],                              // the seven bands, top to bottom
  classes:[ {id, label, colour} ], clusters:[ {id, label} ],
  nodes:  [ { id, label, short, cls, cluster, tier, C, A, D, status, dateStart, dateEnd,
              era, band|null, l0:bool, deg, claims:[t1,t2,t3], hl:number|null } ] }
```
`band` and `era` come from the L0 model for L0 nodes; `era` for every node from its start
date against the era table; `hl` is the start-here number (1 to 14) or null.

### `nodes/<id>.json`
```
{ ...the node's full merged record (narrative or desc, claims, sources, tierRationale,
  chronology, affiliations, conflicts, unverified, coords, locLabel),
  dossier: {...entityDossier} | null,
  connections: [ { id, label, cls, tier, l0, type, claimTier, label, note, dateStart, dateEnd,
                   sources:[{name,url,date}], direction:"out"|"in" } ],   // every sourced edge touching the node
  denials:  [ { by:{id,label}, of:{id,label}, label, claimTier, note, sources } ],   // edges of type denial, either direction
  timeline: [ { id, strand, date, precision, label, text, tier } ],                // events whose node is this id
  foia:     { requests:[...], questions:[...] },                                  // from data/foia-links.json byNode
  members:  [ {id,label,cls,tier} ] | null }                                      // L0 nodes only: the ledger nodes below the floor attached to it
```

### `edges.json`
`[ {a, b, t, tier, label, dateStart} ]` for every sourced edge (about 2,350 rows).

### `timeline.json`
`[ {id, strand, date, precision, label, text, tier, node, era} ]`, 912 rows, sorted by date.

### `claims.json`
`[ {node, label, cls, cluster, tier, text, source:{text,url|null}, denied:bool, open:bool} ]`
one row per claim (5,120). `denied` is true when the node has a denial edge against it;
`open` is true when the node has an open question in the FOIA layer. `source.url` is the
first URL found in the claim's source string, or null.

### `map.json`
```
{ nodes: [ {id, label, short, cls, cluster, tier, C, A, D, dateStart, era, band, hl} ],  // the 125
  direct: [ {a, b, tier, types:[...]} ],           // the L0 model's directEdges
  summarised: [ {a, b, via:[ids]} ],               // the L0 model's summarised edges
  denialPairs: [ {by, of, label} ],
  entryPaths: [ {id, label, blurb, total, onMap, ids:[...]} ],
  cells: { "<band>.<era>": [ids] } }
```
`band` is written into the data here (Design section 4.1): it is the L0 model's band for
the node, and the renderer and the checks read this field, never a rule of their own.

### `threads.json`
From `research/threads.json`, authored (section 5). Each thread: `{ id, label, title,
blurb, steps:[ { node, year, evidence, edge:{type, tier, kind:"direct"|"derived", via:[ids]} } ] }`.

### `patents.json`
From `research/patents-view.json`, `research/observables-view.json`, the file wrapper
index and the drawings. `{ patents:[ {number, node|null, title, status, granted, filed,
inventor, assignee, fee:{...}|null, sheets:[ {k, file, thumb, caption, fig} ],
prosecution:[ {date, kind, label, file|null} ] } ], observables:[...], quotes:[...],
findings:[...], openQuestions:[...] }`. Sheet images are copied to
`app/public/patents/<file>` (the 11 originals, about 3.2 MB in all) and thumbs to
`app/public/patents/thumbs/`.

### `highlights.json`, `foia.json`, `analyst.json`
Highlights: the 14 flags in order with `why`. FOIA: the requests and the node linkage.
Analyst: `{ worker, suggestions:[7 strings] }` copied from `tools/build_dashboard.py`.

## 3. Routes

Exactly Design section 2.1. `#/` home; `#/n/<id>`; `#/n/<id>/map`; `#/n/<id>/hood` (alias
`#/hood/<id>`); `#/hood`; `#/map`; `#/map?cell=<band>.<era>`; `#/t/<id>`; `#/t/<id>/map`;
`#/timeline` with `?era=` and `?scope=n:<id>|t:<id>`; `#/patents/<number>?sheet=<k>`;
`#/evidence?tier=&cls=&cluster=&domain=&denied=1&open=1`; `#/report/n/<id>` and
`#/report/t/<id>`. Unknown routes render a not-found page that names the route. Every
route with an id puts the node's or thread's label in `document.title`.

## 4. Phases and who builds what

| Phase | Deliverable | Agent |
|---|---|---|

| 1c | `research/threads.json`: the eight threads with real evidence lines from the board's own edges and claims | research agent |

| 3 | Timeline (1.7), Threads page (1.6) | after 1a and 1c |
| 4 | Patents (1.8) and the Evidence explorer (1.9) | after 1a |
| 5 | Checks C1 to C16 with poisons in `app/checks/`, Playwright; `look.js` re-pointed; deploy; retire the old shell | last |

## 5. Threads (phase 1c)

Author `research/threads.json` with eight threads in Design section 1.6's order and
titles. Rules: every step is an existing node id; every consecutive pair is joined by an
edge in `data/the-program.json` (any type) or by a shared L0 member (then `kind:"derived"`
with the `via` ids); the `evidence` line is one sentence quoting or closely paraphrasing
the edge's `label` or `note`, or a claim on either node, never a new assertion; `year` is
the node's start year. The missing-scientists thread uses the nodes the board now has
(`missing-scientists-probe-2026`, `william-mccasland`, `podesta-delonge-mccasland-email-2016`
and their neighbours), not placeholders. `tools/verify.py` gains a check `every thread step
is joined to the last by a board edge` with a poison, the way `patents-view.json` is checked.

## 6. Checks (phase 5, listed now so the builders leave hooks)

Design's C1 to C16, each with a poison fixture. Builders must expose what the checks need:
the map publishes `window.__app.map.chips()` (id, box, mode) and `cells()`; the
neighbourhood publishes `ring()`; the timeline publishes `placed()`; every page renders
node links as `<a href="#/n/<id>">` so C1 and C9 can walk the DOM. No check reads a
renderer's private state; every check binds to the DOM or to pixels.

## 7. What the shell agent must not do

Invent copy, sources or figures (placeholders are marked `[placeholder: ...]` and C16 will
reject them, so they must be gone before phase 5). Add a Google Fonts or CDN fetch. Encode
size by importance. Truncate a label. Draw an anonymous mark. Read `dist/the-program.html`
or `ref/the-vanishing-v2.html` for anything but the analyst client and the palette hex
values.
