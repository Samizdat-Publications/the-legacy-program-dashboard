# The rethink, 2 September 2026

Stewart, from the live board, 2 September 2026: the network map at 1,027 nodes is "a
thousand dots that mean nothing"; the white labels never land on what they name; the
patents sheets are not grouped or openable; the Analysis tab was computed for a board of
fifty things; "rethink this entire dashboard, if you think we should scrap stuff and start
over, I'm down. I want the best possible end product so I can share this with my research
friends as a tool that's useful."

This note is the assessment and the proposal. The Design brief that goes with it is
`notes/DESIGN-BRIEF-SHELL-2026-09-02.md`. Nothing here changes the research pipeline,
the checks' philosophy, or the rules in `CLAUDE.md` sections 2, 5 and 6.

## 1. What the board is now

| | |
|---|---|
| research corpus | 1,027 nodes, 5,120 tiered claims, 2,348 hand-written sourced edges, 912 timeline events, 3,389 source URLs, 125 entity dossiers, a FOIA layer, a patents file wrapper, 12 offices with their instruments |
| discipline | every claim tiered and sourced; AARO and DoD capped; provenance checked against opened records; three podcast corpora mined through a mapping, cross-check, triage, verify, decide, build chain |
| shell | `ref/the-vanishing-v2.html`, a 4,728-line page written for a sibling project (missing-persons cases, about fifty nodes), patched at build time by string replacement in four modules |
| surfaces | ten views: Network map, Program map, Patents, Timeline, Geography, Case files, Analysis, The cover-up, Search, Report; a dossier dock; the analyst |
| gate | 56 verify checks, 40 audit re-derivations, 53 runtime assertions, 31 canvas assertions, 20 analyst assertions, all self-tested |

The corpus is the asset. It is unusual: a graph of this size where every edge is sourced
and every claim carries a tier and a URL, with contradictions recorded as findings. That
is what research friends would use. The shell is what stands between them and it.

## 2. What is wrong, surface by surface

**The network map at rest answers no question.** It draws all 1,027 marks and 3,919 pairs
(2,348 sourced edges plus derived shared-employer, shared-location and shared-domain
pairs). The label pass is chosen by space, never by rank, which is right, and at this
density it names 17 nodes out of 1,027 and then drops to zero below zoom 0.62. A reader
sees colour, motion and shape, and cannot tell what any dot is. The dpr bug that put the
names up and to the left of their marks on every Windows screen above 100 percent scaling
is fixed today (`fix/label-dpr-2026-09-02`), but fixing it only makes the names land on
dots that are still anonymous.

**The program map is the good map and it is hidden.** 125 chips, every one named, in
seven bands by measured custody proximity and five eras, orthogonal, with 118 links at
rest and 14 start-here flags. It is the only surface on the board where a first-time
reader can read structure. It sits on the second tab because the 29 August inversion
made the full graph primary.

**The dossier is the value and it is a dock.** Every node's claims, tiers, sources,
denials, connections with evidence, timeline slice and FOIA requests render in a panel
that takes half the window and has no address. Nothing on the board can be linked to.
A friend cannot be sent "look at this node" or "read this thread".

**The timeline is 912 events on one axis.** Its heading still argues the sibling board's
case ("the cases cluster through 2025, the state arrives in April 2026"). The Geography
view's copy is the sibling's too ("three named clusters... the base-rate analysis cuts
against the cluster thesis"). Case files (300) is the sibling's concept wearing this
board's data. Analysis computes patterns designed for fifty missing-persons cases.

**Patents:** eleven sheets in one flat row, 168 by 216 pixel thumbnails, not grouped by
patent, not openable. The file wrapper (rejections, the Sheehy declarations, the appeal
brief) is the strongest documentary material on the board and the tab does not lead
with it.

**The shell is a patch on a patch.** Every UI change is a `must_replace` against the
sibling's markup; the four patch modules total about 6,000 lines of Python strings
containing JavaScript. It works and it is gated, but each change costs an anchor hunt,
and the 184 assertions bind to a DOM that was never designed for this board.

## 3. Who it is for and what they need to do

Stewart's research friends: people who already know the subject, want to check a
specific thing, and will not read a manual. Their jobs, in order of frequency:

1. Look something up by name and get the record: what it is, when, the claims by tier,
   the sources as links, what the government said about it.
2. See what it connects to and WHY, with the evidence on each edge.
3. Follow a thread: the AAWSAP to AATIP to KONA BLUE lineage, the custody chain from
   Grusch back to a contractor, the money, the denial ledger, the patents prosecution,
   the missing scientists.
4. Check a date or an era.
5. Send a link to a colleague that opens on exactly that node or thread.
6. Ask a question and get an answer that cites nodes (the analyst already does this).
7. Take a brief away: a printable page with citations.

None of these jobs begins with a thousand-node hairball. Two of them end with a map.

## 4. The proposal: entity first, map second

**Every node gets a page and an address.** `#/n/<id>` opens the dossier as a full page:
label, class, tier and axes, the narrative, claims grouped by tier with their sources
as links, denials, the sourced connections as a list with the evidence on each, the
node's slice of the timeline, its FOIA requests, and an "on the map" button. This is the
dock's content promoted to the unit of the product. Deep links are the single feature
that makes the board shareable.

**Home is a start page, not a map.** Search first. One paragraph on what the board is
and the rule it follows (section 2 of `CLAUDE.md`, in the reader's language). The
entry paths the L0 model already computes (custody 46, denial 39, foreign 11,
mechanism 10, money 7, witness 7) as cards that open threads. The 14 signed-off
start-here nodes. The counts strip. The analyst's seven suggested questions.

**Threads are first-class.** A thread is an ordered chain of nodes with one line of
evidence per step, curated in data (`research/threads.json`, gate-checked the way
`patents-view.json` is: every step an existing node, every quotation in the claim it
cites). Eight to start: lineage (AAWSAP, AATIP, KONA BLUE), custody (Grusch to a named
contractor), money, denial ledger, the Wilson-Davis notes, patents and prosecution,
the missing scientists, oversight 2023 to 2026. The analyst's scripted branches already
encode three of these in prose.

**The map defaults to the program map.** The orthogonal chip map becomes "The map", the
first thing under the home page, at fit, all 125 names readable. Below the label floor a
cell shows its count and expands on click to its members, so a dot that cannot be named
at the current zoom is never drawn as a dot. The 875 ledger nodes below the floor are
reached through cells, search, and pages, never as anonymous marks.

**The network map becomes the neighbourhood.** Always scoped: the selected node and its
sourced edges at one, two or three hops, drawn with the metro-line rendering, the
animated flow, the collision-tested labels, and the derived pairs muted and optional. It
never draws the whole graph at rest. Opening it with nothing selected shows the
start-here nodes and asks for one. This keeps the two things Stewart asked to keep, the
orthogonal look and the animated lines, and drops the one thing nobody can use.

**Timeline:** lanes by strand (program, witness, oversight, cover-up), eras as the
outer structure, counts per era at low zoom, events at high zoom, and scoping by the
current node or thread. The sibling's argument leaves the heading.

**Patents:** one section per patent (five), each with its sheets in order, a lightbox
that opens a sheet at reading size, the prosecution timeline from the file wrapper, and
the maintenance-fee status. The five observables stay as their own section.

**Evidence explorer:** the claims as a table, filterable by tier, class, cluster, source
domain, "denied", "open question", with the FOIA requests beside the questions they
would close. This replaces Analysis, Case files and The cover-up with one surface that
is computed from the data every build and says so.

**Report:** a printable brief for the current node or thread with numbered citations.
This is what a friend takes away.

**Analyst:** unchanged, with suggestions per page.

## 5. Build strategy: keep the pipeline, retire the inherited shell

Scrapping the research is the one thing not on the table. Scrapping the shell is the
right call. Concretely:

| Keep | Retire |
|---|---|
| `tools/merge.py`, `regrade.py`, `build_l0.py`, `build_design_extract.py`, `build_l0_layout.mjs`, the research files, the dossiers, the golden manifest, `verify.py` and `audit_independent.py` (data checks) | `ref/the-vanishing-v2.html` as the base; `build_dashboard.py`'s `must_replace` patching; the copy inherited from the sibling |
| the packed map renderer in `l0_patches.py` (31 canvas assertions), the edge renderer and label pass in `network_patches.py`, the patents renderer in `patents_patches.py`, the analyst client in `analyst_patches.py` | the DOM-bound runtime assertions, rewritten against the new DOM with the same poisons |
| the design system (dark ground, monospace, the palette, one label size, no size for importance) | ten tabs |

A new shell is its own HTML file with small modules, a hash router, and the same data
files embedded at build; still one self-contained page with no runtime fetch except the
analyst. It is written for this board, so a change is a change and not an anchor hunt.

Phases, each gated and deployed before the next:

| Phase | Builds | Gate |
|---|---|---|
| 0 | this note; the Design brief; Design's mockups at 1366, 1920 and 2560; Stewart's sign-off | none |
| 1 | new shell skeleton: router, home, search, node page, deep links | data checks plus new runtime assertions on the node page and the router |
| 2 | the map as default with cells and expansion; the neighbourhood view ported | the 31 canvas assertions re-pointed; neighbourhood label checks |
| 3 | threads (data file plus page) and the timeline rebuilt | thread integrity checks, the way patents-view is checked |
| 4 | patents regrouped with the lightbox and prosecution timeline; the evidence explorer; report | quotation and provenance checks |
| 5 | analyst suggestions per page; retire the old shell; `look.js` and `walk.js` re-pointed | full gate green, deploy, handoff |

Phase 1 is the one that changes what the board is. It is also the smallest: the data is
already in the built page.

## 6. What must not be lost in the move

- A check that has never been shown to fail is a broken check (`CLAUDE.md` section 5).
  Every new assertion ships with its poison.
- No invented sources, URLs, numbers or quotes, in mockup copy included.
- Size never encodes importance; labels are one size; labels are chosen by space.
- AARO and DoD sources cap at Tier 2 unless the claim is about what they said.
- The page fetches nothing at runtime except the analyst; it stays self-contained.
- Transcripts are never published.

## 7. Decisions for Stewart

1. Audience: a link shared with friends, or public. It changes nothing in the build and
   everything in the name and the front page copy.
2. Name. "The Program" is the working title; the front page needs a real one.
3. Single self-contained file, or a small site (one page, a data file, images). A
   lightbox that opens patent sheets at reading size costs about 3 MB in a single file;
   as a site it costs nothing. The runtime-fetch rule would gain one allowed shape
   (same-origin images).
4. Phase 0 goes to Claude Design with the brief; the build sessions start on Design's
   mockups, not before.
