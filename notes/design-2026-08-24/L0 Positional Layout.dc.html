Reading the map
Position
Column = era of dateStart. Row = band. Inside a cell, most-connected first. All chips are one size: size is not a channel on this board.
Line colour
cyan structural · grey anchor · violet shared-member, with the count as a numeral · red arrow denial, pointing at the subject.
Line routing
Vertical legs run in the gutters between era columns, one lane per edge, longest rise nearest the gutter centre. Dash is claim tier per divergence D1 — solid tier 1, dashed tier 2, dotted tier 3, and never anything else.
Find
Matches dim the rest of the map and take a solid cyan outline, so a result set reads as a shape in the matrix rather than a list. Filters AND together: band: era: cls: tier: cluster: role: id: flag: isolated: and the numeric deg: claims: denials: with > or <. via: searches the off-map shared members, so it finds nodes joined by a person who is never drawn.
Motion
Attested direction only. A travelling dot runs issuer → subject on a denial whose denier the record names, and on selection the selected node’s edges run outward. Nothing else moves.
Denial, three states
Arrowhead means the issuer is named. A perpendicular bar at the midpoint means denial act, denier not established — a bar is not a vector, so it reads as contested rather than as flowing. An association that is not a directed act at all keeps no red: red is reserved for something somebody did.
Shared-member lines
A violet line means two map nodes share two or more members — people, documents or locations that sit off the map and connect directly to both. The gate is two, so one coincidental link never draws a line. Unselected the line carries the count; select either end and it carries the names, with the full list in the dossier row below. Off at rest.
Start here
An amber dashed box and a rank numeral, with a wash on the cell so the region reads before the label does. Drawn offset from the chip, not inside it: it is a pointer somebody chose, not a property of the record, and it must never read as a tier.
Chip marks
Left rule is class — institution, program, event, legislation, document — because once a node carries an image the glyph slot is gone and class needs a permanent home. Entity tier A/B/C is the chip stroke. × means no L0-level link exists at all. ? means the research files disagree about its date. Labels middle-truncate, never end-truncate: the distinguishing token in this corpus is usually the last one.

H · one image per node — the slot, before the data
Requested 24 August: a portrait for a person, a mark for an institution. The slot is built and empty, so the treatment is settled before {{ fig.l0 }} images arrive and nothing has to be redesigned around them. It occupies the space the class letter already had, which is why adding images costs no chip width and removing them loses no information.
I
NO IMAGE — the class letter, not a silhouette
CLEARS — solid frame, credit printed
ASK — dashed frame, reason printed
×
DOES NOT CLEAR / NOT FOUND — nothing is drawn
Rule 1 — Square, never round. A circular crop is an avatar and this is an intelligence product. 16px in the chip, 64px in the dossier, and no other size.
Rule 2 — Greyscale at rest, full colour on selection or a search hit. Not styling: {{ fig.l0 }} institutional logos in brand colour would take over a palette that spends colour on claim tier and edge kind.
Rule 3 — portrait crops to fill, mark fits inside. A cropped logo is a broken logo, and a letterboxed face wastes the slot — so the kind is a field, not a guess.
Rule 4 — An image is a claim. It carries its credit and its clearance, the credit prints in the dossier, and the four-state vocabulary from the sibling board’s PHOTOS.md governs: only CLEARS and ASK are ever drawn. A photograph of the wrong person is a factual error that no amount of framing fixes.
Rule 5 — Missing is not broken. The letter is the answer, and it says what the node is rather than implying a face nobody found. On a load error the record drops to null and the letter returns, the same way the sibling board handles it.

REQUESTED AFTER THE BRIEF · 24 AUGUST
Three things Stewart asked for that the brief does not cover, all built above and recorded here so the implementation session has them in writing.
01 — Search. Working here as the reference and as the design language: one field, space-separated tokens ANDed, a bare token over label / id / roles / cluster / class and key:value filters for band, era, class, tier, cluster, role, id, flag, isolated, and numeric deg / claims / denials with > and <. via: reaches the off-map shared members. Matches dim the map and outline in cyan; the result list is a shortcut, not the answer, because the answer is the shape the matches make in the matrix. On the board this has to be a CMD action to satisfy constraint 4 of the parent brief, and the no-result state must say what it did not search — the 874 nodes below the degree floor.
02 — Named shared members. A line reading 5 is a count with no content. The generator now resolves every member id to a display label, so a selected node’s violet lines name who joins it — two names, then one name and a remainder, then the numeral past four.
03 — Start-here callouts. The board should point at what is worth clicking on open. Design language and data hook above; the editorial pass that decides which nodes is not a design decision and is left as data/l0-highlights.json.
04 — “Is the map claiming Lockheed has no people?” It was, and that was a fault in this comp rather than in the data. lockheed-martin carries {{ lmDeg }} neighbours: {{ lmOnMap }} on the map and {{ lmMembers }} held back by the rollup, among them Ben Rich, Elizondo, Bigelow Aerospace, Air Force Plant 42 and NDAA FY2024 Sec. 1687.
