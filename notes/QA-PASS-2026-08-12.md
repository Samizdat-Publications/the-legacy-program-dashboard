First job per `SESSION-HANDOFF.md`. The board was landed locally, the build pipeline was
run for the first time outside the cloud container, and the network view was inspected at
2550×1465.

**Headline: the documented rebuild command destroyed data on every run.** That is fixed and

## 1. Findings

Severity per the checklist: `BROKEN` (unusable or wrong data) · `UGLY` (works, looks bad) ·
`NIT`.

### #1 · BROKEN · build · the rebuild sequence silently destroyed 35 dates — FIXED

Running the documented sequence produced a board that differed from the shipped one in 42
places. 35 were a real date replaced by `null`.

`regrade.py` read `data/the-program.json` — which already contains `_remediation.json`, its
own previous output, folded in as an authoritative overlay. Its date pass is guarded by
`if p.get("date"): continue`, so on the second run the 40 dates it recovered last time
looked like they had always been there. It emitted an overlay carrying only the 5 it could
still derive, and the next merge overwrote the other 35 with null. The build printed
`all patches applied` throughout.

The remaining 7 differences were tier-rank drift from the same cause.

**Fix.** `merge.py` gained a pristine mode (`MERGE_SKIP`, `MERGE_JSON_OUT`); `regrade.py`
now re-merges *without* its own overlay and scores that, making it a pure function of
`research/` and idempotent by construction — which is what its module docstring always
claimed. Verified: three consecutive full rebuilds now produce a byte-identical
`dist/the-program.html`.

**Guard.** `regrade.guard_no_data_loss()` compares effective board values before and after
and aborts without writing if any `date`, `coords` or `tier` would be lost. It compares the
resulting board rather than the raw overlay, so an overlay that legitimately shrinks —
because the underlying research now carries the field itself — does not trip it. A guard
that cannot tell those apart is a guard that gets switched off.

### #2 · BROKEN · data · five people were on the board twice — FIXED

`p-aaron-lukas` / `aaron-lukas`, and the same for `alexandro-wiggins`,
`jeffrey-nuccetelli`, `dylan-borland`, `joe-spielberger`. Different research agents wrote
the same person under two ids. Each pair split its edges, sources and claims between two
map nodes, and — because `merge.py` falls back to the id when a record has no label — the
twin rendered **its own slug as its display name**: `alexandro-wiggins` instead of
`Alexandro Wiggins`. `l-washington-dc` / `l-dc` was the same bug on a location.

`regrade.py` had a `normalise_id()` that knew about this, but it applied only inside its own
overlay, so `merge.py` saw the normalised id as a *new* node and created an empty record
for it. Two scripts, two copies of the id rules, no shared source of truth.

**Fix.** Canonicalisation moved into `merge.py` as `canonical_id()`, applied at load to
person ids, entity ids, edge endpoints, `locId`/`instId`, timeline `node` refs and
`entityInfo` keys. `merge.py` already merges duplicate ids conservatively, so collapsing the
ids first lets the existing rules union the records. `regrade.py` now imports it.
`_better_label()` stops the id-fallback label beating a real name.

After the fix the five records carry their unioned edges, sources and claims — e.g.
`dylan-borland` went from deg 6 / 10 sources split across two nodes to a single node at
deg 6 / 10 sources, and re-graded B→A on the merged evidence.

**Verified:** 0 duplicate ids, 0 dangling edge endpoints, 0 timeline refs to missing nodes,
0 labels equal to their own id. `timeline_bad_node_ref` in `INTEGRITY.json` went 1 → 0.

### #3 · BROKEN · network, cases · thirteen person plates showed a meaningless name — FIXED

Confirmed by screenshot before the fix: plates reading `JR., J.` and `(SAM), '.`

The parent board took the last whitespace token as the surname. Its 14 people were all
plain `First Last`. This board has 246, sixteen of whom carry a generational suffix, an
honorific or a quoted alias:

| label | was | now |
|---|---|---|
| `Dr. Jesse A. Marcel Jr.` | `JR., D.` | `MARCEL, J.` |
| `James R. Clapper Jr.` | `JR., J.` | `CLAPPER, J.` |
| `John Greenewald Jr.` | `JR., J.` | `GREENEWALD, J.` |
| `William J. Lynn III` | `III, W.` | `LYNN, W.` |
| `Matthew Louis Gaetz II` | `II, M.` | `GAETZ, M.` |
| `'UAP Gerb' (Sam)` | `(SAM), '.` | `GERB, U.` |
| `"Jonathan Grey" (pseudonym)` | `(PSEUDONYM), ".` | `GREY, J.` |
| `General de Brigada Aérea (A) Ricardo Bermúdez Sanhueza` | `SANHUEZA, G.` | `SANHUEZA, R.` |

Five separate people rendered as some variant of `JR., J.` — indistinguishable on the map
and in the dock.

**Fix.** Named patch `person plate name formatter` in `build_dashboard.py`. Strips
parentheticals and quotes, pops trailing generational suffixes, shifts leading honorifics,
and falls back to the whole label rather than to a fragment — a wrong name is worse than a
long one. **Verified against all 246 labels in the shipped build: 0 remaining.**

**Known limitation, not fixed:** `Jesse A. Marcel Sr.` and `Dr. Jesse A. Marcel Jr.` both
render `MARCEL, J.` The `LAST, F.` format cannot separate them. Both are on the board as
distinct nodes and the dock disambiguates them.

### #4 · BROKEN · network · DETAIL panel stated the wrong number of classes — FIXED

The empty-state read *"Five entity classes are clickable: people, institutions, programmes,

### #5 · UGLY · network · person plates overlap and occlude each other's names

**Not fixed.** Along the top edge of the canvas a row of plates collides:
`SCHUMER, C.` / `MOSKOWITZ, J.` / `GILLIBRAND, K.` / `GROTHMAN, G.` / `HEGSETH, P.` — the
last two render as `LLIBRAND, K.` and `SETH, P.` with their left halves painted over.
Screenshot: `notes/qa-2026-08-12/A-toplabels.png`.

They are all clamped to the same y, which suggests nodes pushed outside the vertical bound
are being pinned to the edge rather than repelled back into it — a collision problem on top
of a density problem. This is the checklist's *"the one thing the eye cannot forgive"* item
and it belongs with the density redesign in `CLAUDE-DESIGN-PROMPT.md` §3.1 rather than being
patched blind.

### #7 · NIT · rail · connection-type list clips mid-chip with no scroll affordance

At 2550×1465 the rail shows through `Witness chain` and cuts the chip in half. **All twelve
types are present and reachable** — `.rail-scroll` is `overflow-y: auto`, scrollHeight 860 vs
clientHeight 728 — so this is presentation, not function. Custody chain, Funding channel,
Official denial and Legislative are the four below the fold, which is unlucky: they are the
four the design brief says carry the argument.

### #8 · NIT · tooling · `shoot.js` ink check is dead

Reports `canvasInk: 0` on 21,346 samples for a canvas that is visibly drawing. The renderer
is WebGL2 and `getImageData` on it returns empty without `preserveDrawingBuffer`. The check
that is meant to catch a blank canvas cannot currently fail. Screenshots are still written
and are still the real verification.
